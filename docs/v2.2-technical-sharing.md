# AITestCraft v2.2 技术分享：打通用例平台 AgileTC

## 一、版本概览

v2.2 的核心目标是**打通 AITestCraft 与用例管理平台 AgileTC 的数据闭环**，实现 AI 生成的测试用例自动回写到用例平台，同时新增 KityMinder 脑图格式输出，丰富了用例的可视化呈现方式。

**改动规模**：9 个文件，+253 / -15 行

---

## 二、核心改动详解

### 2.1 用例自动回写：AI → 用例平台的数据闭环

**痛点**：之前 AI 生成用例后，需要人工复制粘贴到用例管理平台，效率低且容易遗漏。

**方案**：在任务提交接口新增 `caseId` 参数，任务完成后自动将结果转换为用例平台所需的 KityMinder 格式，并调用 `saveAiResult` 接口回写。

**数据流**：

```
用户提交任务 (task + caseId)
    ↓
AITestCraft 生成用例
    ↓
解析结果 → KityMinder 格式转换
    ↓
调用 /api/case/saveAiResult 回写
    ↓
用例平台展示用例
```

**关键代码变更**：

| 文件 | 变更 |
|------|------|
| `api/endpoints/tasks.py` | 接口新增 `caseId` 可选参数 |
| `api/services/task_service.py` | 任务完成后调用 `_call_save_ai_result` 回写 |
| `config/config.py` | 新增 `SAVE_AI_RESULT_URL` 配置项 |

**亮点设计**：

- **异步非阻塞**：回写操作使用 `httpx.AsyncClient`，不阻塞主流程
- **容错处理**：回写失败只记录日志，不影响任务状态标记为 success
- **用例为空时跳过回写**：避免向平台写入无效数据

### 2.2 KityMinder 脑图格式：用例的可视化升级

**新增文件**：`formatters/kityminder_formatter.py`（163 行）

KityMinder 是百度开源的脑图渲染引擎，AgileTC 用例平台使用该格式展示用例树。本次新增的 `KityMinderFormatter` 实现了用例到脑图结构的转换：

**树形结构设计**：

```
根节点（需求名称）
├── 模块A (N条)
│   ├── [P0] TC001: 用例名称
│   │   ├── 前置条件: xxx
│   │   ├── 执行步骤
│   │   │   ├── 1. 步骤1
│   │   │   └── 2. 步骤2
│   │   └── 预期结果
│   │       ├── 1. 预期1
│   │       └── 2. 预期2
│   └── [P1] TC002: ...
└── 模块B (M条)
    └── ...
```

**核心特性**：

- **模块分组**：多模块时自动按模块分组，单模块时直接展示用例
- **优先级标签**：用例标题前缀 `[P0/P1/P2]` 直观展示优先级
- **链式结构**：前置条件 → 执行步骤 → 预期结果，形成清晰的执行链路
- **resource 标记**：步骤节点使用 `resource` 字段标注类型（前置条件/执行步骤/预期结果）

### 2.3 结果解析容错：Markdown 降级解析

**痛点**：工作流返回 Markdown 格式的结果时，`_parse_result_data` 中 `json.loads` 失败后直接返回空列表，导致用例丢失。

**修复**：JSON 解析失败后，检测内容是否为 Markdown 格式（以 `|` 或 `#` 开头），尝试用 `parse_markdown_table` 解析。

```python
# 修复前
except (json.JSONDecodeError, ValueError, TypeError) as e:
    logger.warning(f"结果数据 JSON 解析失败: {e}")
    return [], 0  # 直接返回空，用例丢失

# 修复后
except (json.JSONDecodeError, ValueError, TypeError) as e:
    logger.warning(f"结果数据 JSON 解析失败: {e}，尝试 Markdown 解析")
    if raw_result.strip().startswith("|") or raw_result.strip().startswith("#"):
        testcases = parse_markdown_table(raw_result)
        if testcases:
            return testcases, 0
    return [], 0
```

### 2.4 NoneType 防御：知识库上下文空值处理

**痛点**：未关联知识库时 `kb_context` 为 `None`，`len(None)` 抛出 `TypeError`，导致任务重试。

**修复**：

```python
# 修复前
logger.info(f"知识库上下文长度: {len(kb_context)} 字符")

# 修复后
logger.info(f"知识库上下文长度: {len(kb_context) if kb_context else 0} 字符")
```

## 四、架构亮点

### 4.1 格式化器扩展性

本次新增 KityMinder 格式化器，延续了已有的 `BaseFormatter` 扩展模式：

```
BaseFormatter
├── MarkdownFormatter    (v1.0)
├── XMindFormatter       (v1.0)
└── KityMinderFormatter  (v2.2 新增)
```

新增格式只需实现 `format()` 方法，在 `__init__.py` 导出即可，无需修改核心逻辑。

### 4.2 回写解耦

回写逻辑通过配置化的 `SAVE_AI_RESULT_URL` 实现与用例平台的解耦：

- 本地开发：指向 `http://127.0.0.1:8001/api/case/saveAiResult`
- 生产环境：通过环境变量指向 AgileTC 平台地址
- 不传 `caseId` 时完全跳过回写，向后兼容

---

## 五、总结

v2.2 的核心价值在于**打通了 AI 生成用例到用例管理平台的最后一公里**：

1. **自动化闭环**：AI 生成 → 格式转换 → 平台回写，全链路无需人工干预
2. **可视化增强**：KityMinder 脑图格式让用例结构一目了然
3. **健壮性提升**：Markdown 降级解析和空值防御，减少因格式问题导致的用例丢失
